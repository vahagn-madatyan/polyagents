  <behavior>
    ## Score-Change Detection (TRD-03)
    - `tick(current_states, slug_table)` compares current game states against `_prev_game_states` snapshot
    - First time seeing a game: store as baseline, no event fired
    - Score change detected when `current.score_raw != prev.score_raw` for same game_id
    - Detection must be non-blocking: no LLM calls inline in `tick()`, slow-path spawns daemon thread
    - Period transitions received from message queue: `handle_period_transition(msg, slug_table)` routes to slow-path

    ## Event Classification (TRD-02)
    - `_classify_score_change(prev, current)` returns "major" or "minor"
    - Lead change: team that was leading is no longer leading -> "major"
    - Tied-to-leading or leading-to-tied -> "major"
    - Overtime period detected (period contains "OT", "OVERTIME", "ET") -> "major"
    - Period change (current.period != prev.period) without OT -> "minor" (period transitions already handled separately via queue)
    - All other score changes -> "minor"

    ## Fast-Path (TRD-02, minor events)
    - Read `PregameCache.get(game_id)` for cached `llm_home_win_prob`
    - No cache entry -> skip with log
    - Fetch live Polymarket price via `polymarket.get_orderbook_price(market_tag.token_id_yes)`
    - Price fetch error -> skip with log
    - Compute divergence = `abs(llm_prob - live_price)`
    - Divergence < `SPORTS_INGAME_MIN_CONFIDENCE_GAP` (default 0.15) -> skip
    - Divergence >= threshold -> determine outcome (Yes if prob > price, No otherwise), execute trade
    - Check exposure cap before executing
    - Check budget coordinator before executing
    - Dry-run mode: log but do not call CLOB

    ## Slow-Path (TRD-02, major events)
    - Spawn daemon thread running `_run_slow_path(game_id, current_state, market_tag)`
    - Add game_id to `_slow_path_in_flight` set at start, remove on completion
    - Fetch game context via `data_connector.get_game_context(game_state)`
    - Run `executor.analyze_game(game_state, market_tag, game_context)` -> CandidateTrade
    - Update PregameCache with new analysis
    - Apply confidence gap gate (same as fast-path threshold)
    - Apply exposure cap
    - Apply budget gate
    - Dry-run or live execute
    - Allow position reversal: buy opposite token if LLM recommends different side from cache

    ## Per-Game Cooldown (TRD-05)
    - `_last_processed: dict[int, float]` tracks timestamp of last processed event per game
    - `_is_in_cooldown(game_id)` returns True if (now - last_processed) < SPORTS_INGAME_COOLDOWN_SECONDS (default 30)
    - Cooldown checked BEFORE routing to fast or slow path
    - Cooldown timestamp set AFTER processing (both fast and slow path)
    - For slow-path: cooldown set when thread STARTS, not when it completes

    ## In-Flight Guard (TRD-05)
    - `_slow_path_in_flight: set[int]` tracks games currently being analyzed by slow-path
    - `_should_process(game_id)` checks BOTH cooldown AND not-in-flight
    - Prevents duplicate concurrent LLM calls for same game

    ## Game-Ended Safeguards (TRD-02)
    - `handle_game_ended(game_id)` called when current.ended is True
    - Halts all new order placement for that game
    - `_ended_games: set[int]` prevents any future processing
    - Calls `_cancel_blackout_orders(game_id)` to cancel orders within SPORTS_BLACKOUT_MINUTES (default 2) window
    - Order cancellation via `polymarket.client.cancel(order_id)` wrapped in try/except (FOK orders may already be filled)
    - Proactive blackout: `_is_near_resolution(state)` checks final period + elapsed time heuristics, prevents new orders
    - Proactive blackout thresholds are sport-specific; log warning when heuristic is uncertain

    ## Order Logging
    - `_order_log: dict[int, list[dict]]` records every placed order: {order_id, timestamp, market_id}
    - `_log_order(game_id, order_id, market_id)` appends to log
    - In-memory only — lost on restart (acceptable per CONTEXT.md)

    ## Exposure Tracking (TRD-02)
    - `_game_exposure: dict[int, float]` tracks total in-game USD spent per game
    - `_check_exposure(game_id, amount)` returns True if within SPORTS_MAX_GAME_EXPOSURE_USD (default 50.0) cap
    - `_record_exposure(game_id, amount)` updates running total
    - In-game only cap (pre-game separately bounded by BudgetCoordinator.get_sport_cap)

    ## Environment Variables
    - `SPORTS_INGAME_COOLDOWN_SECONDS` (int, default 30)
    - `SPORTS_INGAME_MIN_CONFIDENCE_GAP` (float, default 0.15)
    - `SPORTS_BLACKOUT_MINUTES` (int, default 2)
    - `SPORTS_MAX_GAME_EXPOSURE_USD` (float, default 50.0)
