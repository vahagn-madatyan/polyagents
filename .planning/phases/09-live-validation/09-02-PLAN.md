  <name>Task 1: Live slug validation script (VALID-01)</name>
  <files>scripts/python/validate_slugs.py</files>
  <action>
Create `scripts/python/validate_slugs.py` -- a standalone live validation runner that:

1. **Connects to the live sports WebSocket** via `SportsWSConnector`. Start the connector, wait up to 30 seconds for game states to populate, then snapshot via `get_all_game_states()`.

2. **Exercises the full slug pipeline** via `GammaMarketClient`:
   - Call `build_slug_table(game_states)` to get `(slug_table, unmapped_slugs)`
   - Call `retry_unmapped_slugs(unmapped_slugs, slug_table)` to attempt recovery
   - For each game state, record which league it belongs to, the slug used, whether it mapped successfully, and the lookup method (exact, fallback, or retry)

3. **Categorizes results by sport type** using the 9 known leagues: nfl, nba, mlb, nhl, cfb, cbb, soccer, cs2, tennis.
   - `sports_covered`: leagues that had at least one live game AND all slugs mapped
   - `sports_failed`: leagues that had a live game but slug resolution failed
   - `sports_pending`: leagues from the 9 known that had no live game in this window

4. **Emits structured console output** using `[validate_slugs] event=... key=value` log style (matching existing project conventions).

5. **Writes a JSON report** to `reports/valid-01-slugs.json` (create `reports/` directory if missing). Report structure:
   ```python
   {
       "phase": "VALID-01",
       "run_at": "2026-03-15T...",
       "sports_covered": ["nba", "nhl", ...],
       "sports_failed": [],
       "sports_pending": ["cs2", "tennis", ...],
       "results": {
           "nba": {
               "games_observed": 2,
               "slugs_mapped": 2,
               "slugs_failed": 0,
               "details": [{"slug": "...", "mapped": true, "method": "exact"}]
           }
       },
       "pass": true,  # true only when sports_failed is empty
       "notes": "..."
   }
   ```

6. **Stops the WebSocket connector** in a finally block for clean shutdown.

**Usage:** `SPORTS_EXECUTE_TRADES=false python scripts/python/validate_slugs.py`

The script must be run during an active sports window. It is NOT a test in the `tests/` directory (it requires live Polymarket connectivity). Per CONTEXT.md, if fewer than 9 sports are covered, the phase stays open -- the script just reports what it observed.

1. **Runs both sports and general pipelines concurrently** for a configurable observation window (default 10 minutes, configurable via `VALID03_DURATION_SECONDS` env var).

3. **Captures order-rate evidence** by:
   - Starting the sports pipeline (`agents/sports.py`) as a subprocess
   - Starting the general pipeline entry point as a subprocess (if available; if not, document that only sports pipeline was observed)
   - Redirecting both stdout streams to capture log lines
   - Counting `event=order_rate_sample` log lines from InGameTrader (added in Plan 01)
   - Counting any `event=trade_placed` or equivalent log lines from the general pipeline
   - Tracking the peak observed `orders_per_60s` value from order_rate_sample lines

4. **Produces a structured JSON report** written to `reports/valid-03-rate-limit.json`:
   ```python
   {
       "phase": "VALID-03",
       "run_at": "2026-03-15T...",
       "duration_seconds": 600,
       "dry_run": true,
       "sports_order_rate_samples": 12,
       "general_order_rate_samples": 0,
   ```
